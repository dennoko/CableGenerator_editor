# UV展開ロジック解説

## 概要

CableGenerator は2つのUVチャンネルを自動生成する。

| チャンネル | 用途 | Unity API |
|---|---|---|
| UV0 (`uv`) | テクスチャマッピング（タイリング対応） | `Mesh.SetUVs(0, ...)` |
| UV1 (`uv2`) | ライトマップ用（0〜1に一意展開） | `Mesh.SetUVs(1, ...)` |

## UV座標系の考え方

押し出しメッシュは「断面 × スプライン経路」の2次元構造を持つ。この2軸がそのままUVの2軸に対応する。

```
V (スプライン方向)
^
|  ┌────────────────┐  t=1 (終点)
|  │                │
|  │   メッシュ面   │
|  │                │
|  └────────────────┘  t=0 (始点)
+-----------------------> U (断面の周方向)
  0                    1
```

- **U軸**: 断面プロファイルの周方向の位置
- **V軸**: スプラインに沿った進行方向の位置

---

## UV0（テクスチャ用）の計算

### U座標

断面プロファイル（`CableProfile`）の `GetUCoords()` が返す値をそのまま使用する。

各プロファイルの実装:

| プロファイル | U座標の決め方 |
|---|---|
| HeavyDutyCableProfile | `i / segments`（円周の等分割） |
| FlatCableProfile | 累積周長 / 全周長（辺の長さに比例） |
| ParallelWireProfile | 左の円: 0〜0.5、右の円: 0.5〜1.0 |

例えば HeavyDutyCableProfile (segments=8) の場合:

```
頂点0: U=0.000  (0°)
頂点1: U=0.125  (45°)
頂点2: U=0.250  (90°)
  ...
頂点8: U=1.000  (360° = 0°に戻る)
```

### V座標

スプラインの累積距離にタイリングスケールを掛けた値:

```csharp
float v = (splineLength * t) * uvTiling;
```

- `splineLength`: スプライン全長（ワールド単位、例: 2m）
- `t`: スプライン上の正規化位置（0〜1）
- `uvTiling`: ユーザー設定のタイリング倍率

#### 具体例

スプライン長 = 2m、uvTiling = 3 の場合:

```
t=0.0 → V = 2 × 0.0 × 3 = 0.0
t=0.5 → V = 2 × 0.5 × 3 = 3.0
t=1.0 → V = 2 × 1.0 × 3 = 6.0
```

V が 0〜6 の範囲になるため、テクスチャが V 方向に6回繰り返される。これにより長いケーブルでもテクスチャが引き伸ばされず、一定密度でタイリングされる。

### UV0の展開イメージ

```
V (タイリングあり)
^
6.0 ┌────────────────┐
    │  テクスチャ×6  │
    │  繰り返し      │
    │    :           │
3.0 │────────────────│
    │    :           │
0.0 └────────────────┘
    0              1.0  → U
```

## UV1（ライトマップ用）の計算

### U座標

UV0と同じく `profileUs[j]` を使用（0〜1）。

### V座標

タイリングなしの正規化位置 `t` をそのまま使用:

```csharp
uv2s.Add(new Vector2(profileUs[j], t));
```

- `t` は常に 0〜1 の範囲

### UV1の展開イメージ

```
V (正規化、0〜1)
^
1.0 ┌────────────────┐
    │                │
    │  メッシュ全体  │
    │  が一意に展開  │
    │                │
0.0 └────────────────┘
    0              1.0  → U
```

### なぜUV0とUV1を分けるのか

| 要件 | UV0 | UV1 |
|---|---|---|
| 値の範囲 | 0〜∞（タイリング） | 0〜1（正規化） |
| 重複 | あり（テクスチャ繰り返し） | なし（一意展開が必須） |
| 用途 | テクスチャの見た目制御 | ライトマップベイク |

ライトマップは各ピクセルが固有のライティング情報を持つため、UV空間上で重複があるとベイク結果が破綻する。UV1は全頂点を0〜1に一意にマッピングすることでこの要件を満たしている。

## コード上の該当箇所

`CableGenerator.cs` の `RebuildMesh()` 内、頂点生成ループ:

```csharp
for (int i = 0; i <= resolution; i++)
{
    float t = (float)i / resolution;       // 0〜1
    float v = (splineLength * t) * uvTiling; // タイリング付き距離

    for (int j = 0; j < profileVertCount; j++)
    {
        // UV0: テクスチャ用（Vはタイリングあり）
        uvs.Add(new Vector2(profileUs[j], v));

        // UV1: ライトマップ用（Vは0〜1に正規化）
        uv2s.Add(new Vector2(profileUs[j], t));
    }
}
```

メッシュへの反映:

```csharp
generatedMesh.SetUVs(0, uvs);   // UV0
generatedMesh.SetUVs(1, uv2s);  // UV1（ライトマップ）
```
