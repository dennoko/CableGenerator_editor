# UV展開ロジック解説

## 概要

CableGenerator は2つのUVチャンネルを自動生成する。

| チャンネル | 用途 | Unity API |
|---|---|---|
| UV0 (`uv`) | テクスチャマッピング（タイリング対応） | `Mesh.SetUVs(0, ...)` |
| UV1 (`uv2`) | ライトマップ用（0〜1に一意展開） | `Mesh.SetUVs(1, ...)` |

## UV座標系の考え方

押し出しメッシュは「断面 × スプライン経路」の2次元構造を持つ。この2軸がそのままUVの2軸に対応する。

```
V (スプライン方向)
^
|  ┌────────────────┐  t=1 (終点)
|  │                │
|  │   メッシュ面   │
|  │                │
|  └────────────────┘  t=0 (始点)
+-----------------------> U (断面の周方向)
  0                    1
```

- **U軸**: 断面プロファイルの周方向の位置
- **V軸**: スプラインに沿った進行方向の位置

## UV0（テクスチャ用）の計算

### U座標

断面プロファイル（`CableProfile`）の `GetUCoords()` が返す値をそのまま使用する。

各プロファイルの実装:

| プロファイル | U座標の決め方 |
|---|---|
| HeavyDutyCableProfile | `i / segments`（円周の等分割） |
| FlatCableProfile | 累積周長 / 全周長（辺の長さに比例） |
| ParallelWireProfile | 左の円: 0〜0.5、右の円: 0.5〜1.0 |

例えば HeavyDutyCableProfile (segments=8) の場合:

```
頂点0: U=0.000  (0°)
頂点1: U=0.125  (45°)
頂点2: U=0.250  (90°)
  ...
頂点8: U=1.000  (360° = 0°に戻る)
```

### V座標

スプラインの累積距離にタイリングスケールを掛けた値:

```csharp
float v = (splineLength * t) * uvTiling;
```

- `splineLength`: スプライン全長（ワールド単位、例: 2m）
- `t`: スプライン上の正規化位置（0〜1）
- `uvTiling`: ユーザー設定のタイリング倍率

#### 具体例

スプライン長 = 2m、uvTiling = 3 の場合:

```
t=0.0 → V = 2 × 0.0 × 3 = 0.0
t=0.5 → V = 2 × 0.5 × 3 = 3.0
t=1.0 → V = 2 × 1.0 × 3 = 6.0
```

V が 0〜6 の範囲になるため、テクスチャが V 方向に6回繰り返される。これにより長いケーブルでもテクスチャが引き伸ばされず、一定密度でタイリングされる。

### UV0の展開イメージ

```
V (タイリングあり)
^
6.0 ┌────────────────┐
    │  テクスチャ×6  │
    │  繰り返し      │
    │    :           │
3.0 │────────────────│
    │    :           │
0.0 └────────────────┘
    0              1.0  → U
```

## UV1（ライトマップ用）の計算

UV1はライトマップベイクのために、全頂点を0〜1のUV空間に一意に展開する必要がある。複合形状（複数ループを持つプロファイル）では、各ループの断面を独立した「短冊（ストリップ）」として扱い、**棚パッキング（Shelf Packing）アルゴリズム**で0〜1空間に詰め込む。

### 棚パッキングの流れ

1. **短冊の生成**: 各ループの周長とスプライン長からアスペクト比を算出し、短冊を作成
2. **ソート**: 高さ降順でソート
3. **パッキング**: 棚（段）に短冊を左から詰め、収まらなければ次の段へ
4. **スケーリング**: 全体が0〜1空間に収まるまでスケールを調整（最大16回試行）
5. **リスケール**: パッキング後、0〜1空間を最大限に活用するようリスケール

### UV1座標の計算

各頂点のUV1座標は、その頂点が属するループの短冊パッキング位置に基づいて計算される:

```csharp
// ループ内での局所U座標
float localU = (float)localJ / (vertsPerLoop - 1);
// 閉じ頂点（末尾）は先頭と重ならないようオフセット
if (localJ == vertsPerLoop - 1)
    localU = (float)(localJ - 1) / (vertsPerLoop - 1) + 0.5f / (vertsPerLoop - 1);

// パッキング済み短冊の位置に変換
uv1.x = strip.packU + localU * strip.packW;
uv1.y = strip.packV + splitT * strip.packH;
```

### UV1の展開イメージ（複合形状の場合）

```
V (0〜1)
^
1.0 ┌──────────────────────┐
    │                      │
    │  ┌────┐  ┌────┐     │
    │  │loop│  │loop│     │
    │  │ 0  │  │ 1  │ ... │
    │  └────┘  └────┘     │
    │                      │
0.0 └──────────────────────┘
    0                    1.0  → U
```

単一ループのプロファイル（HeavyDutyCableProfile など）では、短冊が1つだけとなり、0〜1空間全体を使用する。

### なぜUV0とUV1を分けるのか

| 要件 | UV0 | UV1 |
|---|---|---|
| 値の範囲 | 0〜∞（タイリング） | 0〜1（正規化） |
| 重複 | あり（テクスチャ繰り返し） | なし（一意展開が必須） |
| 用途 | テクスチャの見た目制御 | ライトマップベイク |

ライトマップは各ピクセルが固有のライティング情報を持つため、UV空間上で重複があるとベイク結果が破綻する。UV1は棚パッキングにより全頂点を0〜1に一意にマッピングすることでこの要件を満たしている。

### 既知の制限

メッシュ生成時にループ境界の頂点を共有しているため、UV空間でのアイランド分割（1ループを複数の短冊に分割）は現在無効化されている。有効化するにはループ分割点での頂点複製が必要。

## コード上の該当箇所

`CableGenerator.cs` の `RebuildMesh()` 内:

**UV0（テクスチャ用）**:
```csharp
float v = (splineLength * t) * uvTiling;
uvs.Add(new Vector2(profileUs[j], v));
```

**UV1（ライトマップ用）**:
```csharp
// 事前にパッキングレイアウトを計算
var uv1Layout = CalculateUV1Layout(perimeters, loopCount, splineLength);
// 各頂点のUV1をパッキング位置から計算
uv2s.Add(CalculateUV1(uv1Layout, loopIdx, localU, t, i));
```

メッシュへの反映:

```csharp
generatedMesh.SetUVs(0, uvs);   // UV0
generatedMesh.SetUVs(1, uv2s);  // UV1（ライトマップ）
```
