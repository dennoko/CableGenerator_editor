# 技術参照資料

## 概要
要件定義で示した機能を実装するための技術的詳細と参照情報をまとめる。主に Unity の API、数学的アルゴリズム、最適化手法を扱う。

## 主要コンポーネント（概念）
- `SplineContainer` / `Spline`（Unity Splines パッケージ）: 曲線データ保持・編集
- `CableGenerator`（独自コンポーネント）: スプラインを受けてメッシュを生成・更新
- `CableProfile`（ScriptableObject）: 断面プロファイル（頂点・法線・U）を提供
- `MeshFilter` / `MeshRenderer`: 生成メッシュの表示

## 重要アルゴリズムと手法

### 1) スプラインのサンプリングと局所フレーム
- サンプリングは一定間隔、または曲率依存の可変間隔で行う。
- 各サンプリング点について `Position`、`Tangent`（一階微分）を取得し、`Up` と組み合わせて右方向ベクトル (`Right`) を計算する。
- 回転の滑らかさには Rotation Minimizing Frames（RMF）や Quaternion Slerp が有効。

### 2) 押し出し（Extrusion）によるメッシュ生成
- 2D 断面の頂点をサンプリング点の局所フレームにマッピングして 3D 頂点を生成する。
- 各セグメントで四角形を生成し三角形に分割してインデックスを構成する。

### 3) UV の計算
- U: 断面上の割合（profile が提供）
- V: スプライン方向の累積距離を基にタイリングスケールを掛ける

### 4) 法線
- 自動再計算に頼らず、断面の 2D 法線を 3D に変換して明示的にセットすることで継ぎ目の不具合を防ぐ。

### 5) パフォーマンス最適化
- `Mesh` の再割り当てを避ける（キャッシュ、`mesh.Clear()`、`mesh.MarkDynamic()`）
- 頂点・インデックス・UV 用の `List<T>` を再利用
- 影響を受けるセグメントのみを差分再計算する部分最適化

## Unity API 参照（実践的ヒント）
- `Handles.DrawBezier`, `Handles.PositionHandle`, `HandleUtility.GetHandleSize` — Scene GUI 表示・操作
- `Undo.RecordObject`, `EditorUtility.SetDirty` — Undo / シーンのダーティフラグ
- `Mesh.SetVertices`, `Mesh.SetNormals`, `Mesh.SetUVs`, `Mesh.SetTriangles` — 大きな配列を一括設定
- `mesh.MarkDynamic()` — 頻繁に更新するメッシュへの助言
- `SplineContainer`, `Spline`, `SplineUtility.Evaluate`, `SplineUtility.CalculateLength` — Splines パッケージのユーティリティ

## 数学的補足
- ベジェ曲線の1次微分で接線を得る
- 接線・上方向から外積で右方向を計算
- RMF（Rotation Minimizing Frames）でねじれを最小化

## 用語・参照先
- Spline / SplineContainer: Splines パッケージの曲線データ。`SplineUtility` の各種ユーティリティが使える。
- CableProfile: 断面プロファイル。`ScriptableObject` で作成し、デザイナーが差し替えられることを想定。
- SplineUtility.Evaluate: 指定 t における `position, tangent, up` を取得するために利用する関数。

## 実装ヒント（チェックリスト）
- Mesh の初期化は一度だけ行い、毎回 `mesh.Clear()` して再利用すること
- 頂点バッファはクラスフィールドの `List<T>` を Clear/Reuse し GC を抑えること
- 法線は自前で計算してセットする（`RecalculateNormals()` に全面依存しない）
